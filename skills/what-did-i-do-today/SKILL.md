# /what-did-i-do-today — 내가 오늘 뭘 시켰나

## 활성화 조건

`/what-did-i-do-today` 나 `$what-did-i-do-today` 로 불렀을 때만 돌려. 이름만 나온 건 호출이 아니야 — `disable-model-invocation` 이 그 경로를 막으니까, 실행하지 말고 슬래시로 불러달라고 안내해. 회고나 작업 내역 얘기가 나왔다고 알아서 집어 들지 마.

## 뭐 하는 스킬이냐면

세션을 여러 개 동시에 굴리면 **하루가 끝날 때 내가 뭘 시켰는지 기억이 안 나.** 각 세션 안엔 남아 있지만 흩어져 있고, 세션을 하나씩 열어보는 건 회고가 아니라 고고학이야.

이 스킬은 전사에서 **사용자가 실제로 입력한 것만** 뽑아서 세션별로 모아줘.

## 핵심 — 뭐가 "내가 입력한 것"인가

전사의 `type: "user"` 에는 사용자가 친 것과 **시스템·AI 가 넣은 게 섞여** 들어가. 구분 안 하고 세면 노이즈에 실제 입력이 묻혀. 실제로 한 세션에서 `type: "user"` 204건 중 사용자가 친 건 29건뿐이었어 — 나머지는 대부분 도구 실행 결과였고.

다행히 스키마에 판별 필드가 있어. **문자열로 추측하지 말고 이 필드를 써.**

| 필드 | 값 | 뜻 |
|---|---|---|
| `origin.kind` | `human` | 사람이 한 것 |
| | `task-notification` | 백그라운드 작업 완료 알림 |
| | `peer` | 다른 Claude 세션이 보낸 메시지 |
| `promptSource` | `typed` / `queued` / `suggestion_accepted` | 사람이 입력한 경로 |
| | `system` / `sdk` | 프로그램이 넣은 경로 |
| `isMeta` | `true` | 주입된 내용 |
| `isSidechain` | `true` | 서브에이전트 내부 대화 |

본문 표식으로 한 번 더 걸러. `<system-reminder>`, `<command-name>`, `<local-command-stdout>`, `<bash-stdout>`, `<cross-session-message` 가 있으면 사용자 발화가 아니야. 단 **`<bash-input>` 은 사람이 `!` 로 직접 친 명령이라 포함해.**

판별 필드가 둘 다 없는 옛 전사는 **사람이 친 거라고 단정하지 말고 `[판별불가]` 로 따로 표시해.** 추측으로 "당신이 이걸 입력했습니다" 라고 말하지 마.

## 실행 절차

### 1. 기간 확인

기본은 24시간이야. 사용자가 기간을 말했으면 거기에 맞춰.

```bash
"$SKILL_DIR/bin/collect.py"              # 최근 24시간 (기본)
"$SKILL_DIR/bin/collect.py" --hours 48
"$SKILL_DIR/bin/collect.py" --days 7
"$SKILL_DIR/bin/collect.py" --json       # 구조화 출력
```

"어제부터", "이번 주", "3일치" 같은 표현은 시간으로 바꿔서 넘겨. **애매하면 기본 24시간으로 돌리고 "더 볼까요?" 라고 덧붙여** — 기간 확정하려고 되묻느라 사용자를 붙잡지 마.

`SKILL_DIR` 은 이 `SKILL.md` 가 있는 디렉터리야.

### 2. 요약해 — 원문을 그대로 쏟지 마

스크립트 출력은 **재료지 답이 아니야.** 그대로 붙여넣으면 세션을 하나씩 여는 거랑 다를 게 없어.

프로젝트별로 묶어서 이렇게 답해.

```
오늘(9/13) 4개 프로젝트, 8개 세션에서 71건 입력하셨습니다.

my-mac-tools (41건, 17:34~17:10)
  맥북 덮개 닫고 작업 유지 기능 — 데몬 방식을 조사했다가 제품 기능으로 전환,
  기존 기능과의 충돌 테스트까지. 프로브 결과 3건 PASS 확인.

mobile-easy-drive-uploader (5건, 16:14~17:10)
  ML Kit 온디바이스 이미지 인식으로 사진 카테고리 자동 분류 — 설계 문서 작성 단계.
```

원칙:

- **사용자가 뭘 시켰는지**를 써. AI 가 뭘 했는지가 아니야. 이 스킬은 사용자의 기록이거든.
- 한 세션에 주제가 여러 개면 **주제 단위로 나눠.** 시간순으로 늘어놓는 건 요약이 아니야.
- **중간에 방향이 바뀐 지점**을 짚어줘 (위 예의 "데몬 방식 → 제품 기능으로 전환"). 회고할 때 제일 쓸모 있는 정보야.
- 입력이 적은 세션(1~2건)은 한 줄로 붙여.
- 사용자가 원문을 보고 싶다고 하면 그때 스크립트 출력을 보여줘.

### 3. 구분을 드러내

요약 끝에 **직접 입력 / AI·시스템** 건수를 같이 적어. 사용자가 요청한 구분이고, 숫자로 보여야 의미가 있어.

```
직접 입력 71건 · AI/시스템 자동 12건 (작업 완료 알림 3, 다른 세션 메시지 5, 슬래시 명령 2, 기타 2)
```

`[판별불가]` 항목이 있으면 **몇 건인지 밝히고 왜 확정을 못 하는지 한 줄로 적어.** 사람 입력에 조용히 섞지 마.

## 동작 원칙

- **판별은 필드로 해.** `origin` 이랑 `promptSource` 가 있는데 본문 문자열로 추측하지 마. 표식 매칭은 그 필드가 없을 때 쓰는 보조 수단이야.
- **확정할 수 없으면 확정하지 마.** `[판별불가]` 를 사람 입력으로 올려 세지 마.
- **원문을 요약 없이 쏟지 마.** 사용자가 묻는 건 목록이 아니라 "내가 오늘 뭘 했나" 야.
- **전사를 고치지 마.** 이 스킬은 읽기 전용이야. `~/.claude/projects/` 는 대화 기록 원본이라 손대면 복구가 안 돼.
- **내용을 밖으로 보내지 마.** 전사엔 코드·경로·사내 정보가 들어 있어. 요약을 외부로 보내거나 파일로 남기는 건 사용자가 요청했을 때만 해.
- **긴 붙여넣기는 요약에서 접어.** 사용자가 터미널 출력을 통째로 붙여넣은 것도 "직접 입력" 은 맞지만, 요약에선 "테스트 결과 붙여넣음" 정도로 줄여.

## 다루는 범위

**기본은 Claude Code 전사(`~/.claude/projects/*/*.jsonl`)야.** 판별 필드가 있어서 구분을 확정할 수 있어.

Codex(`~/.codex/sessions/`)는 `--codex` 를 줬을 때만 포함해. Codex 전사엔 **사람 입력을 표시하는 필드가 없어.** `event_msg`/`user_message` 가 사용자 입력처럼 보이지만, 실제로는 프로그램이 넣은 내용도 같은 자리에 들어가(확인된 예: cmux 승인 평가 세션은 전부 자동 생성). 그래서 포함하더라도 **"확정 불가" 로 표시하고 사람 입력 건수엔 합치지 마.**
