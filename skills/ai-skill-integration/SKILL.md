# /ai-skill-integration — Claude 와 Codex 의 스킬을 맞춘다

## 이 스킬이 푸는 문제

같은 스킬이 두 에이전트에 따로 들어가 있으면 **어느 쪽이 최신인지 알 수 없는 상태**가 만들어진다. 한쪽에서 고치고 다른 쪽을 잊으면, 다음에 그 스킬을 쓸 때 옛 버전이 돈다. 에러가 나지 않으므로 한참 뒤에야 알아챈다.

이 저장소는 그 상태를 실제로 한 번 만들었다. `bin/install.sh` 가 **저장소 스킬**에 대해 그 문제를 심링크로 풀었다. 이 스킬은 **저장소 밖 스킬** — 각 머신에만 있는 업무용 스킬들 — 을 다룬다.

## 타협 불가 가드레일

- **방향은 반드시 사용자에게 묻는다.** 분석 결과가 한쪽으로 쏠려 보여도 자동으로 정하지 않는다. 스킬은 사용자가 쓰는 도구이고, 어느 쪽이 "맞는" 버전인지는 파일 시각이 아니라 사용자만 안다.
- **묻기 전에 분석 결과를 먼저 보여준다.** 근거 없이 "어느 쪽으로 갈까요?" 라고 물으면 사용자가 판단할 재료가 없다.
- **삭제하지 않는다.** 한쪽에만 있는 스킬은 채우기만 한다. 반대편에서 지우지 않는다.
- **덮어쓰기 전에 백업한다.** 경로를 사용자에게 알린다.
- **저장소가 관리하는 스킬은 건드리지 않는다.** 그건 `bin/install.sh` 의 일이고, 심링크라 이미 양쪽이 같다.
- **계보가 다른 스킬은 자동 처리하지 않는다.** 아래 참조.

## 실행 절차

### 1. 분석 — 먼저 돌리고, 결과를 사용자에게 보여준다

```bash
"$SKILL_DIR/bin/skill-sync.py" analyze
```

`SKILL_DIR` 은 이 `SKILL.md` 가 있는 디렉터리다. 읽기 전용이며 아무것도 바꾸지 않는다.

출력은 세 덩어리다.

| 덩어리 | 뜻 |
|---|---|
| 동기화가 필요한 스킬 | 한쪽에만 있거나 내용이 갈린 것. 상태·최신 쪽·양쪽 mtime |
| 집계 | `claude 가 최신 N개 / codex 가 최신 M개 / 이미 같음 K개` |
| 제외 | 저장소 관리 · 다른 패키지 · 계보 충돌 |

**전부 붙여넣지 말고 사용자가 결정하는 데 필요한 것만 추린다.** 집계 한 줄과, 한쪽으로 쏠리지 않는 예외 항목이 핵심이다.

### 2. 최신 판정을 어떻게 하는지 알고 보고한다

판정은 세 단계다.

1. **내용 해시** — 파일 경로와 바이트를 합쳐 sha256. 같으면 `동일` 로 끝난다. 심링크가 같은 원본을 가리키면 그것도 `동일` 이다.
2. **최신 mtime** — 다르면 각 스킬 디렉터리에서 가장 최근에 수정된 파일의 시각을 비교한다.
3. **내용 규모** — 2번 판정을 반증하는 보조 신호. 아래 참조.

**mtime 은 추정이지 사실이 아니다.** 복사·체크아웃·백업 복원이 시각을 바꾸고, 내용이 옛것인데 시각만 새것일 수 있다. 그래서 이 스킬은 판정을 근거로 쓰되 **결정은 사용자에게 넘긴다.** 보고할 때 이 한계를 함께 말한다.

#### 내용 규모가 mtime 을 반증한다

최신으로 판정된 쪽의 총 바이트가 반대쪽의 **60% 미만**이면 `!` 로 표시하고 의심 블록에 따로 뽑는다.

`mtime` 이 새로운데 내용이 훨씬 작다면 그건 갱신이 아니라 **래퍼 껍데기이거나 잘린 사본**일 가능성이 높다. 실제로 그런 일이 있었다.

```
meeting-minutes
  claude  6파일 29880B   2026-02-26   ← 본체 (references/ + scripts/ 포함)
  codex   2파일  1470B   2026-07-09   ← "# Codex wrapper for meeting-minutes"
```

mtime 만 보면 codex 가 4개월 더 최신이다. 그대로 밀었으면 **24줄 래퍼가 400줄 본체를 덮었다.** 규모가 5% 라는 사실이 그것을 막았다.

**의심 항목은 방향을 정하기 전에 내용을 직접 열어 확인한다.** 규모도 신호일 뿐이다 — 정당하게 줄어든 리팩터링일 수도 있다. 자동으로 방향을 뒤집지 않는다.

### 3. 방향을 묻는다 — 생략 금지

`AskUserQuestion` 으로 묻는다. 선택지는 둘이다.

| 선택지 | 하는 일 |
|---|---|
| `claude → codex` | Claude 쪽을 원본으로 삼아 Codex 를 맞춘다 |
| `codex → claude` | Codex 쪽을 원본으로 삼아 Claude 를 맞춘다 |

**집계가 갈리면 그 사실을 질문에 담는다.** 예를 들어 `claude 가 최신 21개 / codex 가 최신 1개` 라면, 한 방향으로 밀 때 그 1개가 옛 버전으로 덮인다는 것을 알린다. 그 1개의 이름을 함께 보여준다.

쏠린 쪽으로 밀되 예외만 따로 처리하고 싶다는 답이 나오면 `--only` 로 나눠 두 번 돌린다.

```bash
"$SKILL_DIR/bin/skill-sync.py" apply --direction claude-to-codex
"$SKILL_DIR/bin/skill-sync.py" apply --direction codex-to-claude --only meeting-minutes
```

### 4. 적용

```bash
"$SKILL_DIR/bin/skill-sync.py" apply --direction <고른 방향> [--only a,b,c]
```

스크립트가 하는 일.

- 덮어쓸 대상이 있으면 `~/.claude/backups/skill-sync-<타임스탬프>/` 에 먼저 복사한다
- 원본 쪽에 없는 스킬은 **건너뛴다.** 그 방향으로는 채울 수 없다는 뜻이며, 반대편에서 지우지 않는다
- 심링크는 따라가 **실체를 복사**한다. 대상 머신에 없는 경로를 가리키는 링크를 만들지 않기 위해서다

### 5. 검증하고 보고한다

적용 후 다시 분석해 남은 차이를 확인한다.

```bash
"$SKILL_DIR/bin/skill-sync.py" analyze
```

보고할 것 — 방향, 적용·건너뜀 개수, 백업 경로, **남은 차이**(있으면 왜 남았는지). 그리고 **새 스킬은 다음 세션부터 로드된다**는 점을 알린다.

## 제외되는 세 부류

### 저장소 관리

`~/my/Dev/jjw-ai-skills/skills/` 에 있는 이름은 건드리지 않는다. 이미 양쪽이 같은 저장소를 가리키는 심링크이고, 갱신은 `git pull` 과 `bin/install.sh` 가 한다. 여기서 복사하면 **심링크를 실체로 바꿔 드리프트를 다시 만든다.**

### 다른 패키지

description 이 `[OMX]` 로 시작하면 oh-my-codex 가 설치한 것이다. 그 패키지가 관리하므로 여기서 옮기지 않는다.

### 계보 충돌 — 같은 이름, 다른 출처

**한쪽만 `[OMX]` 인 경우다.** 이름이 같아서 동기화 대상처럼 보이지만 실제로는 서로 다른 스킬이다. 어느 방향으로 밀어도 한쪽이 사라진다.

실제 사례 — `configure-notifications`

| 쪽 | 정체 |
|---|---|
| Claude | 개인 스킬. Discord·Telegram·Slack 웹훅을 세션 훅에 연결 |
| Codex | `[OMX] Configure OMX notifications` — 다른 패키지의 것 |

**자동으로 처리하지 않는다.** 사람이 한쪽 이름을 바꾸거나 한쪽을 버리기로 정해야 한다. 스크립트는 이 부류를 `**` 로 표시하고 이유를 함께 출력한다.

## 동작 원칙

- **mtime 으로 단정하지 않는다.** 판정 근거일 뿐이다. "codex 가 최신" 이라고 보고하되 "그러므로 codex 가 맞다" 고 쓰지 않는다.
- **`!` 가 붙은 항목은 반드시 내용을 열어본다.** 규모가 크게 줄어든 쪽을 원본으로 삼는 것은 대개 사고다. `apply` 도 그 방향이면 경고를 띄우지만, 막지는 않는다 — 정당한 축소일 수 있어서다.
- **한 방향으로 미는 것이 기본이지만 강제는 아니다.** 예외가 한둘이면 `--only` 로 나눠 도는 편이 낫다. 21개를 맞추자고 1개를 잃을 이유가 없다.
- **적용 후 반드시 다시 분석한다.** 스크립트가 "적용 N개" 라고 말한 것과 실제로 같아진 것은 다르다.
- **양쪽 디렉터리가 다 있어야 한다.** `~/.codex/skills` 가 없으면 Codex 를 안 쓰는 머신이므로, 만들지 말고 그 사실을 알리고 멈춘다.
- **이 스킬은 커밋하지 않는다.** 대상이 전부 `~/` 아래이고 저장소 밖이다.

## 참고: 스크립트 인터페이스

```
skill-sync.py analyze [--json]
skill-sync.py apply --direction claude-to-codex|codex-to-claude [--only a,b,c]
```

`--json` 은 분류 결과를 그대로 준다 — `state`, `newer`, `suspect`, `excluded`, 그리고 양쪽의 `*_mtime` / `*_bytes` / `*_files`. 사용자에게 표를 다르게 그려주고 싶을 때 쓴다.
