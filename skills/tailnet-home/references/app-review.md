# 홈 앱 리뷰 절차

홈에 올린 앱들을 한 번에 점검할 때 쓰는 절차. 2026-11-10~11 밤에 앱 7개를 이 방식으로 리뷰하고 고쳤다
(결과는 각 앱 폴더의 `REVIEW.md`). 기준은 `app-checklist.md`.

## 순서

1. **앱 목록**: `tailnet-home.py status` 의 앱 줄. 각 앱의 소스는 root 폴더, proxy 앱은 `~/Library/LaunchAgents/<service>.plist` 의
   `ProgramArguments`·`WorkingDirectory`. 사용자가 빼라고 한 앱은 목록에서 지운다(지금: 도트 데모 게임 `games`).
2. **사용성 먼저, 코드 다음.** 사용성은 `bin/phone-check.mjs --all --skip <뺄 앱>`(한 번에 요약) 또는 `<id>` 로 시작해서, 앱의 핵심 일을 폰 폭으로 끝까지 해 본다.
   코드는 정확성, 보안(tailnet 의 모든 기기에 열림), 자원, 시험 빈틈.
3. **항목마다 점수**: 영향 40 + 확실성 30 + 고치기 안전 30.
   - 영향: 40 데이터 손실·보안·핵심 고장 / 30 자주 겪는 불편·보이는 버그 / 20 가끔 / 10 이하 미관
   - 확실성: 30 재현함 / 20 코드로 분명 / 10 의심
   - 안전: 30 작고 국소적·시험으로 확인·결정 불필요 / 15 중간 / 0~5 설계 결정·큰 개편·공유 인프라
   - **80 이상은 고치고 시험으로 확인, 미만은 메모.** 앱 전체 성적(사용성·코드 /100)은 따로.
4. **2단계(사용자가 계속하라고 했을 때)**: 메모 중 60 이상이면서 합리적 기본값이 분명한 것을 고친다. "결정 필요"라도
   되돌리기 쉬우면 추천안으로 하고 `REVIEW.md` 에 "내가 정한 것·되돌리는 법"을 적는다. 큰 개편·데이터 형식·외부 비용·
   보안 정책(serve 설정 등)은 선택지와 추천만.
5. **결과물**: 앱 폴더의 `REVIEW.md`(사용성 표, 코드 표, 고친 것, 메모, 밤 작업 절). 여러 앱을 묶은 요약은 세션별로
   볼 수 있게 한 장(Artifact 등)으로.

## 안전 규칙 (어긴 적이 있어 적음)

| 규칙 | 겪은 일 |
|---|---|
| 고치기 전에 바꿀 파일을 백업(세션 임시 폴더, 원래 경로대로) | 대부분 git 이 아님 |
| 고치기 직전마다 그 폴더의 Claude 세션이 busy 인지 본다(`session_watch.py status`). busy 면 사본에서 준비하고 idle 때 옮김 | 리뷰 중에도 그 프로젝트 세션이 일하고 있었음 |
| 사용자가 빼라고 한 앱은 열지도 않는다. 하위 에이전트에게 맡겼으면 바로 알리고, 이미 바뀐 파일은 백업으로 되돌린다 | 제외 지시가 늦게 닿아 게임 폴더가 잠깐 바뀌었음 |
| 확인용 Chrome 은 `--remote-debugging-pipe`, 임시 서버·프록시는 `[::1]` | 127.0.0.1 은 tailnet 에서 닿아 데이터 사본이 몇 분 열려 있었음 |
| 실제 데이터에 쓰는 버튼, AI·TTS·Drive 같은 비용 호출은 누르지 않음. 데이터 사본·가짜 실행 파일로 | |
| 서버를 고쳤으면 전체 시험·린트가 **모두 통과한 걸 본 뒤에** `launchctl kickstart -k`, 직접 주소와 홈 경유 둘 다 200. 한 명령에 이어 쓸 땐 `&&` 로 실패하면 멈추게 | 시험 결과 줄만 찍고 `;` 로 이어 쓰다가 실패(pytest 2·ruff 7)를 보기 전에 빌드·재시작까지 간 적이 있음 |
| 꺼진 앱(홈 스위치 꺼짐)은 켜지 않고 임시 인스턴스로만 확인 | |
| 리뷰 문서에 비밀·키를 옮기지 않음. 정적 root 앱의 `REVIEW.md` 는 tailnet 에 공개됨 | |
| 하위 에이전트가 보고한 시험 결과는 마지막에 직접 다시 돌린다(저장소가 정한 런타임으로: 예 Node 22). 이 맥에서는 `~/my/Dev/home/test-apps.sh` 가 앱마다의 명령·런타임을 알고 한꺼번에 돌림 | 내 셸이 Node 21 이라 vitest 가 "실패"처럼 보였음 |
