# 홈 앱 기준 (폰에서 쓰는 앱)

홈(`/apps/<id>/`)에 올리는 앱이 지켜야 할 것. 2026-11-10 홈 앱 7개를 리뷰했더니 **모든 앱**에서 같은 문제가
되풀이돼서 모았다(누를 곳이 작음, 다크 모드 없음, 뒤로 가기에 상태가 사라짐, 검사 도구가 tailnet 에 포트를 엶).
앱을 만들 때, 올리기 전에, 고친 뒤에 이 순서로 본다.

## 1. 한 번에 보기: `phone-check`

```bash
node ~/.claude/skills/tailnet-home/bin/phone-check.mjs <id>          # 홈의 앱
node ~/.claude/skills/tailnet-home/bin/phone-check.mjs http://[::1]:<포트>/   # 올리기 전 로컬 서버
node ~/.claude/skills/tailnet-home/bin/phone-check.mjs --all --skip games   # 홈과 켜진 앱 전부, 끝에 요약(꺼진 앱은 건너뜀)
```

390×844 터치 화면으로 밝게·어둡게 열어 보고 아래를 말해 준다. 누르지 않고, 페이지가 여는 동안 보내는 쓰기 요청(GET·HEAD·OPTIONS 밖)은 막는다(막은 수를 알려 줌). GET 으로 상태를 만드는 앱(예: 기사 도장이 첫 화면을 열 때 오늘의 퀴즈 세트를 만듦)은 막을 수 없다.
누를 곳은 그려진 상자가 아니라 실제로 눌리는 범위로 잰다(가운데서 위아래·좌우 21px 지점이 그 요소에 닿는지). 투명한 `::before` 로 넓힌 링크도 통과한다. 아래쪽에 있는 것도 화면 가운데로 스크롤해 같은 방법으로 잰다.
가로 넘침 · 스크립트 오류와 4xx/5xx(절대경로가 `/apps/<id>/` 아래에서 깨지는 것 포함) · 44px 보다 작은 누를 곳 ·
12px 보다 작은 글자 · 다크 모드를 따르는지. 화면 읽기가 이름을 못 읽는 누를 곳(아이콘만 있는 단추 등)은 ✗ 로 세지 않고 알려만 준다. 화면 두 장을 남긴다. 가로 넘침이나 오류가 있으면 종료 코드 1, 페이지를 아예 못 열면 2.
가로 넘침은 폰 폭 390px 과 비교한다. viewport meta 가 없거나 넓은 요소 때문에 폰이 페이지를 축소해 보여 주면(`visualViewport.scale` < 1, 글자가 다 작아짐) 그것도 ✗ 로 잡는다. meta 가 있고 `overflow-x:hidden` 이면 축소 없이 잘리는데, 이건 이 검사 밖이다.

`phone-check.mjs` 를 고쳤으면 `node phone-check.test.mjs` 로 판정을 확인한다. 지금까지 오판했던 경우(투명 `::before`, 경로 줄 링크, 닫힌 `<details>`, 짧은 다크 화면, 후리가나, placeholder, 열 때 POST, 못 여는 주소, 축소된 넓은 화면(meta 없음·hidden 포함))를 담은 시험 화면 21개와 인자 3가지를 `[::1]` 의 빈 포트에 띄워 확인한다. 걸리는 시간은 약 12초.

## 2. 화면

| 기준 | 왜 | 어떻게 |
|---|---|---|
| 누를 곳 44px 이상 (폰에서) | 7개 앱 모두 20~36px 버튼·링크가 있었음 | `@media (pointer: coarse) { … min-height: 44px }` — 맥 화면은 그대로 둘 수 있음 |
| 다크 모드 | 폰이 밤에 어두운 모드. 없던 앱 셋 | 색을 `:root` 토큰으로, `@media (prefers-color-scheme: dark)` 에서 토큰만 바꿈. 그림·사진 칸은 밝은 바탕을 유지해도 됨 |
| 뒤로 가기·새로 고침에 상태가 남음 | 목록 → 상세 → 뒤로 가 맨 위로 튀거나 검색어가 사라졌음 | 화면 상태는 주소의 해시(`#/p/<id>`, `#/q/<검색어>`)에, 목록 스크롤은 떠날 때 기억했다 돌아올 때 복원 |
| 오류는 한국어로, 다음 할 일과 함께 | 연결이 끊기면 "Failed to fetch" 가 그대로 나왔음 | `fetch` 실패를 잡아 "연결이 끊겼습니다. 홈이 켜져 있는지 보고 다시 눌러 주세요" |
| 긴 화면의 뒤로·거르기는 위에 붙임 | 맨 아래에서 열리는 기록 화면에서 위로 한참 올라가야 했음 | `position: sticky; top: 0` 띠 |
| 경로는 상대경로 | 앱은 `/apps/<id>/` 아래에서 열림 | `./x.js`, 서버는 `X-Forwarded-Prefix` |
| 폰에서 Mac 에만 뜨는 창 | Drive 로그인 창이 Mac 에 떠서 폰에서 3분 기다림 | 그런 버튼은 "Mac 화면에서 로그인하세요"라고 말함 |

## 3. 서버 (proxy 앱)

| 기준 | 왜 |
|---|---|
| `::1` 에서만 듣기 | 127.0.0.1 은 tailnet 에서 홈을 거치지 않고 바로 닿음(userspace tailscaled) |
| 쓰기 요청은 앱 전용 헤더(예: `X-<앱>: 1`)와 Host 검사 | CSRF·DNS 리바인딩. 홈 앱들은 같은 출처라 헤더만으로는 다른 앱 스크립트를 못 막음(홈 리뷰 C1, 아직 결정 필요) |
| `Content-Length` 는 숫자·0 이상·상한 | `-1`·`abc` 에서 스레드가 붙잡히거나 응답 없이 끊겼음 |
| 소켓·외부 호출에 시간 제한 | 응답 없는 상대 하나가 서버를 세움 |
| 상태 파일 경로는 설정으로 바꿀 수 있게 | 시험용 두 번째 인스턴스가 실제 기록을 지울 뻔했음 |
| 지우기는 소프트 삭제(되살리기) | 폰에서 잘못 누르기 쉬움 |
| 누가 닿는지는 Tailscale ACL 로 정함(사람이 관리 콘솔에서) | tailnet 에 다른 사람·회사 기기가 있으면 홈과 127.0.0.1 에 연 것 모두에 닿음. 앱 쪽에서 막을 수 없음 |

## 4. 시험

| 기준 | 왜 |
|---|---|
| 서버 단위 시험 + 폰 폭 화면 시험 | 폰 폭 시험이 없던 앱에서 작은 누를 곳·뒤로 가기 문제가 남아 있었음 |
| 헤드리스 Chrome 은 `--remote-debugging-pipe` | `--remote-debugging-port` 는 127.0.0.1 포트를 열어, 시험 도는 동안 tailnet 기기가 그 브라우저를 조종할 수 있음. 구현 예: `bin/phone-check.mjs` |
| 임시 서버·프록시도 `[::1]` | 같은 이유 |
| 시험은 실제 데이터를 건드리지 않음 | 임시 폴더 사본, 비용 드는 호출(AI·TTS·Drive)은 가짜로 |

## 5. 리뷰를 남길 곳

앱 폴더의 `REVIEW.md`(또는 `REVIEW-<날짜>.md`). 그 폴더의 Claude 세션이 바로 읽을 수 있게.
정적 root 앱은 `REVIEW.md` 도 tailnet 에 공개되니 비밀·개인 경로를 적지 않는다.
