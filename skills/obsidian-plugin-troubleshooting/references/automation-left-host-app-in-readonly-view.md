# 자동화로 호스트 앱의 보기 모드를 바꾼 뒤 되돌리지 않아, 편집이 안 되는 것처럼 보인다

## 환경

| 항목 | 값 |
|---|---|
| OS | macOS 26.6.2 |
| 호스트 앱 | Obsidian 1.13.7 |
| 자동화 경로 | Local REST API 플러그인 4.0.2 (`POST /commands/<id>/`) |

특정 앱의 문제가 아니다. **편집 모드와 읽기 전용 모드가 따로 있는 앱을 외부에서
명령으로 조작하는 모든 경우**에 해당한다.

## 증상

앱이 멈추지도 않고 오류도 없는데 **입력이 전혀 안 된다.** 글자를 드래그해 선택하는
것만 되고 타이핑·붙여넣기·커서 이동이 먹지 않는다. 사용자에게는 앱이 고장난 것으로
보인다.

## 원인

**자동화가 보기 모드를 읽기 전용으로 바꿔놓고 되돌리지 않았다.** 읽기 모드는 설계상
선택과 드래그만 허용하고 입력을 받지 않는다. 즉 고장이 아니라 **정상 동작하는 다른
모드**에 들어가 있는 것이다.

두 가지가 겹쳐 발견이 늦어진다.

1. **토글 명령은 상태를 되돌려주지 않는다.** `markdown:toggle-preview` 같은 명령은
   현재 상태를 뒤집을 뿐이라, 호출 전 상태를 모르면 되돌릴 수도 없다. 검증하려고
   한 번 호출하고 잊으면 그대로 남는다.
2. **모드가 세션을 넘어 저장된다.** Obsidian 은 leaf 별 보기 모드를 워크스페이스
   상태에 저장하므로, 앱을 다시 켜도 읽기 모드가 유지된다. "재시작했는데도 안 된다"
   가 되어 원인이 자동화라는 데까지 생각이 닿지 않는다.

확인은 워크스페이스 상태 파일에서 한다. 문제가 된 leaf 만 `mode` 가 다르다.

```bash
python3 - <<'PY'
import json, io
w = json.load(io.open('.obsidian/workspace.json', encoding='utf-8'))
def walk(n):
    if n.get('type') == 'leaf':
        st = n.get('state', {}).get('state', {})
        print(st.get('file'), '→', st.get('mode'))
    for k in ('children', 'main', 'left', 'right'):
        v = n.get(k)
        if isinstance(v, list):
            for c in v: walk(c)
        elif isinstance(v, dict): walk(v)
walk(w)
PY
```

```
Work/.../2026-09-18 ....md → preview   ← 이것만 읽기 모드
Work/.../2026-09-15 ....md → source
Personal/....md            → source
```

## 해결

**사용자 손으로 단축키를 누르는 것이 가장 빠르다.** Obsidian 은 `Cmd+E`
(Windows·Linux 는 `Ctrl+E`) 로 편집/읽기 모드를 뒤집는다. 자동화 경로가 살아 있다면
같은 토글 명령을 한 번 더 호출해도 된다.

**앱이 실행 중일 때 워크스페이스 상태 파일을 손으로 고치지 않는다.** 앱이 메모리의
레이아웃을 기준으로 파일을 다시 쓰므로 수정이 날아가고, 최악에는 레이아웃이 깨진다.
파일을 고치려면 앱을 먼저 완전히 종료한다.

이 사례에서는 되돌리려는 시점에 REST API 포트가 닫혀 있어 자동화로 복구할 수 없었고,
사용자에게 단축키를 안내하는 것이 유일한 경로였다. **자동화가 만든 상태를 자동화로
되돌릴 수 있다고 전제하면 안 된다.**

## 재발 방지

- **토글 명령으로 상태를 바꾸지 않는다.** 가능하면 원하는 상태를 직접 지정하는
  명령·API 를 쓴다. 토글밖에 없다면 **호출 전 상태를 먼저 읽어 기록**하고, 끝나면
  그 상태로 복원한다.
- **복원을 `finally` 에 둔다.** 검증 중에 예외가 나거나 중간에 끊기면 복원이
  건너뛰어진다. 이 사례가 정확히 그랬다.
- **사용자의 실제 문서를 대상으로 모드를 바꾸지 않는다.** 검증은 임시 문서에서 하고,
  임시 문서를 지우기 전에 모드를 되돌린다. 문서를 지우면 그 leaf 가 다른 문서를
  물게 되어, 바꿔놓은 모드가 **사용자의 실제 문서로 옮겨간다.**
- **자동화가 앱을 재시작시킨 뒤에는 무엇이 활성 상태인지 다시 확인한다.** 재시작은
  이전 레이아웃을 복원하므로, 자동화가 열어둔 임시 문서가 아니라 사용자가 보던
  문서가 앞에 올 수 있다.
- **되돌리기 전에 대상이 맞는지 확인한다.** 활성 문서를 먼저 조회하고 토글한다.
  확인 없이 토글하면 엉뚱한 문서의 모드를 뒤집는다.
- 조작이 끝났으면 **눈에 보이는 상태를 점검 항목에 넣는다.** 파일 내용만 맞는지
  보지 말고, 사용자가 돌아왔을 때 쓸 수 있는 상태인지 본다.
