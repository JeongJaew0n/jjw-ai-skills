# /chrome-extension-ai-guidance — Chrome 가이드를 이 프로젝트에 도입할지 판단한다

## 이 스킬이 하는 일

Chrome 팀이 **코딩 에이전트로 확장 프로그램을 만들 때** 쓰라고 내놓은 도구 모음이 있다. 이 스킬은 그 문서를 지금 시점에 읽어와, **호출된 프로젝트에 맞는지** 따지고, 결론을 문서로 남긴다.

**가이드 내용을 여기에 복사해두지 않는다.** 그 페이지는 Chrome 팀이 계속 고치고, 복사본은 곧 거짓이 된다. 매번 원문을 받아 본다.

## 원문

| 문서 | URL |
|---|---|
| **본문** — 코딩 에이전트로 확장 프로그램 빌드 | `https://developer.chrome.com/docs/extensions/ai/build-with-ai?hl=ko` |
| Modern Web Guidance (스킬팩) | `https://developer.chrome.com/docs/modern-web-guidance?hl=ko` |
| 에이전트용 Chrome DevTools | `https://developer.chrome.com/docs/devtools/agents?hl=ko` |
| Extensions and AI 상위 | `https://developer.chrome.com/docs/extensions/ai?hl=ko` |

```bash
curl -fsSL --max-time 25 "https://developer.chrome.com/docs/extensions/ai/build-with-ai?hl=ko" -o /tmp/chrome-ai.html
```

HTML 이라 태그를 걷어내고 읽는다. **본문 헤딩이 그대로 분석 축이 된다.** 헤딩 구성이 바뀌었으면 아래 축 목록이 낡은 것이므로, 원문을 기준으로 삼고 그 사실을 문서에 적는다.

받아오지 못하면(네트워크 차단 등) **추측으로 분석하지 않는다.** 실패를 알리고 멈춘다.

## 타협 불가 가드레일

- **분석만 한다. 아무것도 설치하지 않는다.** 스킬팩 설치, MCP 서버 등록, `CHROMEWEBSTORE.md` 생성은 전부 환경·저장소를 바꾸는 일이다. 문서에 "이렇게 하면 된다" 까지만 쓰고, 실행은 사용자가 별도로 지시할 때 한다.
- **확장 프로그램 프로젝트인지 먼저 확인한다.** 아니면 분석하지 말고 그 사실을 알리고 멈춘다. 관계없는 프로젝트에 그럴듯한 도입 문서를 남기지 않는다.
- **원문을 받지 못하면 멈춘다.** 기억으로 채우지 않는다.
- **권고를 그대로 옮기지 않는다.** 각 항목마다 **이 프로젝트에서** 값어치가 있는지 판단하고 근거를 붙인다. 근거 없는 "도입 권장" 은 쓰지 않는다.

## 실행 절차

### 1. 대상이 맞는지 확인

인자로 경로가 왔으면 그것, 없으면 현재 디렉터리다.

```bash
ls manifest.json 2>/dev/null && cat manifest.json | head -30
```

판정 기준은 **루트의 `manifest.json`** 이고, 그 안에 `manifest_version` 과 `name` 이 있으면 확실하다.

| 상황 | 처리 |
|---|---|
| `manifest.json` 있고 `manifest_version: 3` | 그대로 진행 |
| `manifest_version: 2` | 진행하되 **MV2 는 지원 종료 대상**이라는 점을 문서 맨 앞에 적는다 |
| 없음 | **멈춘다.** "확장 프로그램 프로젝트가 아니다" 라고 알리고, 사용자가 그래도 원하면 그때 진행한다 |

확장 프로그램이 맞으면 현재 상태를 함께 본다 — 빌드 도구, 테스트 유무, `CHROMEWEBSTORE.md` 존재 여부, 이미 설치된 에이전트 설정(`CLAUDE.md`, `AGENTS.md`, `.claude/`).

### 2. 원문을 받아 분석 축을 뽑는다

위 `curl` 로 받아 헤딩과 본문을 읽는다. 2026-09-17 기준 본문이 권하는 것은 셋이었다. **이건 참고이고, 실제 축은 그때 받은 원문에서 뽑는다.**

| 축 | 내용 |
|---|---|
| Modern Web Guidance 스킬팩 | `chrome-extensions` + `modern-web-guidance` 스킬. `modern-web-guidance` CLI 로 설치하면 자동 갱신 |
| 에이전트용 Chrome DevTools | 플러그인·확장·MCP 서버 형태. 에이전트가 Chrome 에서 직접 디버그 |
| `CHROMEWEBSTORE.md` | 에이전트에게 스토어 배포 절차를 알려주는 규약 파일 |

### 3. 축마다 이 프로젝트 기준으로 판단한다

각 축에 대해 네 가지를 채운다. **빈칸을 남기지 말고, 모르면 모른다고 쓴다.**

- **권고 내용** — 원문이 무엇을 하라고 하는가 (한두 줄)
- **이 프로젝트의 현재** — 지금 어떻게 하고 있는가. 파일·설정으로 근거를 댄다
- **판정** — `도입` / `보류` / `미도입` 중 하나
- **근거** — 왜 그 판정인가. 프로젝트의 사실에 붙인다

판정 기준을 이렇게 잡는다.

| 판정 | 언제 |
|---|---|
| 도입 | 지금 없는 것이고, 있으면 실제로 덜 틀리거나 빨라진다 |
| 보류 | 값어치는 있으나 전제가 안 갖춰졌다 (예: 아직 스토어 배포 계획이 없다) |
| 미도입 | 이 프로젝트에 해당하지 않거나, 이미 다른 방식으로 해결돼 있다 |

**이미 갖춘 것을 "도입" 으로 쓰지 않는다.** 예를 들어 에이전트 설정이 이미 정리돼 있다면 스킬팩 설치가 그 위에 무엇을 더하는지, 혹은 충돌하는지를 따진다.

### 4. 기존 에이전트 설정과의 충돌을 본다

이 축은 원문에 없지만 **반드시 확인한다.** 스킬팩은 `~/.claude/skills` · `~/.codex/skills` 에 스킬을 설치하는데, 그곳이 이미 관리되고 있으면 부딪힌다.

```bash
ls ~/.claude/skills ~/.codex/skills 2>/dev/null | head
ls ~/.claude/skills/chrome-extensions ~/.claude/skills/modern-web-guidance 2>/dev/null
```

확인할 것.

- 같은 이름의 스킬이 이미 있는가
- 그 디렉터리가 **심링크로 저장소에 묶여 있는가** — 그렇다면 외부 설치 도구가 링크를 실체로 바꿔 드리프트를 만들 수 있다
- 자동 갱신(CLI)이 기존 설치 방식과 충돌하지 않는가

**충돌 가능성이 보이면 그것만으로 `보류` 사유가 된다.** 문서에 적는다.

### 5. 문서로 남긴다

```
docs/decisions/chrome-extension-ai-guidance.md
```

`docs/decisions/` 가 없으면 만든다. 이미 같은 파일이 있으면 **덮어쓰지 말고** 읽어서 갱신하고, 판정이 뒤집힌 항목은 이유와 함께 남긴다.

템플릿은 아래 `산출 문서` 절 그대로 쓴다.

### 6. 보고

판정 집계(`도입 N / 보류 M / 미도입 K`), 문서 경로, 그리고 **다음에 사용자가 지시해야 할 것**을 짧게 말한다. 이 스킬이 설치까지 하지 않았다는 점을 분명히 한다.

## 동작 원칙

- **원문 확인일을 반드시 적는다.** 그 페이지는 바뀐다. 날짜가 없으면 나중에 이 문서가 유효한지 판단할 수 없다.
- **원문에 없는 축을 만들지 않는다.** 단 4번(기존 설정 충돌)은 예외이며, 그 사실을 문서에 표시한다.
- **설치 명령은 적되 실행하지 않는다.** `하려면` 항목에 그대로 쓰고 사용자가 판단하게 둔다.
- **`도입` 을 기본값으로 삼지 않는다.** Chrome 팀의 권고는 일반론이고, 이 프로젝트에 맞는지는 별개다. 셋 다 `미도입` 이 정답인 프로젝트도 있다.
- **이 스킬은 커밋하지 않는다.** 산출물은 대상 프로젝트의 `docs/` 이고, 커밋은 그 저장소의 규약을 따라 사용자가 지시할 때 한다.
